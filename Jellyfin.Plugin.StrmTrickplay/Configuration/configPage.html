1. 基本

关闭后完全透传 Jellyfin 核心行为（.strm 将没有进度条预览，也不再探测媒体信息）。

2. 目录与解析

默认 {name}.trickplay 与 trickplay。目录内规范：<宽> - <每行张数>x<每列张数>/<序号>.jpg，例如 320 - 10x10/0.jpg。
媒体文件被改名后仍能找到瓦片（可能误匹配，默认关闭）。
自动模式与 Jellyfin 官方 12.2 的推断算法一致；显式填值则以你为准——预览缩略图位置有偏移时用它校准（常见值 2000 / 5000 / 10000）。

3. 缓存

.strm 的时长常常探测不到，此时用较短的"未知时长缓存"，等探测补齐时长后会自动按官方算法重算间隔。

4. STRM 媒体信息探测

Jellyfin 会把 .strm 当"快捷方式"跳过库扫描探测，导致条目没有时长 / 编码 / 分辨率（还会出现"看几秒就被标记已看"、无法按分辨率筛选）。打开后插件会用 ffprobe 探测远端直链补齐这些信息。
关闭后计划任务会直接跳过；已有的媒体信息不受影响。
库扫描新增条目后按下面的"防抖时间"批次探测，不必手动跑任务。
Jellyfin 核心对每个 .strm 条目在每次点播时都会强制跑一次远端 ffprobe（按路径后缀判断，与信息是否齐全无关）， 这是起播慢的主因。打开后：只有"确实是 .strm + 已有对应媒体流 + 已知时长"的条目才跳过；其余原样探测，不影响未探测过的条目。
